# 首版实现范围

## 0.6.1 金属材料使用习惯优化

1. 新实验默认名称为 `{experiment}_{sample}`，普通测量不追加操作流水号。快速添加、安排测试、启用备样和临时样品统一默认 S 前缀，跨样品组连续分配。物理样品编号按安排时的顺序固定，实际开始顺序由 Run.number 记录，重排不重编号。
2. 同一样品的不同测量保持稳定 sampleId。文件夹名默认是实验编号加样品编号；同一件样品的第 2 次及以后测量加 `_02`、`_03`，只统计这件样品，不跟其他样品连号。资料库里未经设置保存的旧默认规则 `{experiment}_{sample}_{run:03}` 在打开时改为上述规则，只重算尚未开始的自动名称。已经开始的文件名、Run.snapshot 和原始时间保持不变。在设置里明确保存过的 `{run}` 规则继续沿用，界面说明该数字是全表计划序号，不是样品编号。
3. 样品准备独立记录 composition、processing、heatTreatment、otherTreatment，分别对应成分、加工工艺、热处理制度、其他工艺。字段可选；空字符串或缺字段表示未填写，“无”表示明确没有。支持文字、单位和工序顺序，不从 NOHR_aged 等原始标记推断或拆分。成分的 wt.% / at.% 由用户明确填写，不换算。
4. 快速添加、编辑、批量设置、具体样品覆盖、规划状态展示与搜索支持上述字段；沿用参数和连续录入保留制备信息。测量的实验制度独立保存，避免和制备热处理混淆。
5. 新字段经主进程与备份校验，保存在既有实体 JSON 的可选扩展中，SQLite 表、user_version、备份版本和 schemaVersion 保持 1，不回填旧 Run.snapshot。导入、XLSX/CSV/JSON 和 HTML/PDF 保留原始状态、单位、空值与开始时制备状态。旧自定义“成分”等字段与新增字段分别保留，不能串列或覆盖。
6. 在独立临时目录完成编号、重测、旧模板切换、历史冻结、旧备份、同名自定义列往返以及真实桌面、窄窗口和打包程序验证。本轮仅本地交付，不自动推送或公开发布。

## 删除与右键菜单

样品组、样品、测量和没有实际记录的实验可以删除。右键菜单放已有的编辑、复制、安排、查看和排序，不在菜单里开始、完成或中断。

1. `deleteGroups` 删除同一实验里没有 Run 的样品组，并去掉这些组的样品、未开始测量，以及指向这些测量的事件。准备数量随组消失。组里已有 Run 时整次拒绝。
2. `deleteSamples` 移出没有 Run 的样品及其测量和对应事件。样品组与 preparedCount 保留，计划数减少，备样数增加。
3. `deleteItems` 只删除 pending 或 skipped、且没有 Run 的测量。不改其余测量的 plannedName、nameNumber 和顺序。若该样品再无测量、也无 Run，则去掉样品，使其回到备样。进行中、已完成、已中断一律拒绝。
4. `deleteExperiment` 只删除没有任何 Run 的实验及其样品组和未开始测量。已有 Run 的实验保留全部记录、快照和原始时间。
5. 删除在确认后一次提交。失败整次回滚。不提高 schemaVersion 或 user_version。

## 文件夹名

界面只呈现一种数据文件夹名：实验编号加样品编号。同一件样品的后续测量加 `_02`。材料、状态和制度写在样品与测量记录中。设置里的「其他写法」继续保存原有 `namingPattern`；已经开始的文件名、快照和原始时间不变。不提高 schemaVersion 或 user_version。

## 0.6 同步辐射现场升级

1. 材料短名与原始状态分别保留；名称可组合实验编号、材料、状态、物理样品编号、原位/离位、测量技术、制度短码、批次和稳定计划序号。提供规则预设、历史复用、实时预览、原生复制、手动临时名称与自动避重。
2. 同一物理样品可以预排不同制度和重复测量；方式、制度详情与批次保存在操作计划，追加制度不增加物理样品数或消耗备样，真正重测保留 repeatOf。
3. 常用快速添加支持上述字段；规划页提供测量计划、批量配置和追加入口，现场可直接配置或追加。离位同样能填写完整制度。队列与回看按制度、批次及名称搜索，已有实际记录显示历史快照。
4. 命名序号在规划时预留，调整或乱序开始不会变动名称；开始后的名称、测量快照与原始时间固定。主进程原子校验批量命令，保存失败重试同一请求不增加重复操作。
5. 新实体属性可选，SQLite 表/索引与 v1 格式保持不变；补新旧备份兼容、非法字段、名称冲突、计数、快照和各格式导出测试。真实桌面及打包程序完成离线多制度与响应丢失验收。
6. 限于本项目记录和规划，不读取、解析、匹配实际 SXRD 数据，不与外部数据处理软件集成。名称生成独立于文件和文件夹是否存在。

依据用户批准的 LabRecord 实现计划：在 LabRecord 项目目录 创建独立 Electron、React、TypeScript、SQLite 项目，中文界面，Windows x64 可双击启动，单机离线。

1. **实验规划**：保留旧表字段；数量明确为准备数量，安排测试后创建具体样品和计划操作；备样独立统计。支持编号、制备/试剂名称、命名规则、自定义字段与单位、多行粘贴、复制、批量编辑、展开样品和排序。
2. **现场记录**：待测队列、当前样品、时间线；同一时间仅一个进行中的操作。开始与完成立即写入，完成后仅选中下一项；备注、问题、图片、文件名和扫描编号可补充。支持临时样品、备样、重测、跳过、中断。
3. **可追溯记录**：实际操作保存开始时的计划；时间修正保留原值与修改历史；退出后不推断结束时间。起止时间用于大致对应仪器数据。
4. **保存与交换**：自动保存、失败保留输入和重试；限定桌面接口和进程隔离；XLSX/CSV/粘贴映射；旧标记不生成实际操作；Excel/CSV/版本化 JSON 导出；完整备份、附件校验及恢复前备份。
5. **交付验收**：准备 6 / 安排 4 / 备样 2；验证备样、重测、跳过、中断、连续点击、午夜、重启、时间修正、保存失败、中文、前导零、单位和空值；在打包程序中完成离线全流程及键盘和布局检查，交付源码、软件、示例、说明，更新工作区索引。

首版未包含云同步。实验时间的准确度取决于点击时机和电脑系统时钟；精确时间仍以仪器文件为准。

## 0.2 升级要求

依据用户对首版界面的反馈，简化常用录入流程，保留完整记录能力：

1. 名称与原始样品状态分开；厚度与宽度常用，高度可选，保留单位、空值和每个具体样品的覆盖参数。
2. 一次录入样品及准备/测试数量；支持连续添加、沿用参数和键盘操作。规划表减少横向列数，更多参数在需要时展开。
3. GitHub 私人仓库同步全部实验和现场图片；离线可继续记录。处理双方修改、在用操作、失败重试和接收前备份，不静默覆盖。
4. 一次生成 PDF、独立 HTML、完整 JSON、图片和 agent 阅读说明；报告给出完成情况及缺失记录，保留计划与实际、原始时间和修改历史。
5. 在打包程序中验证录入、报告、旧记录兼容和两个独立数据目录的真实私人仓库往返同步。

升级仍不控制仪器，不修改仪器原始数据，不推断未知时间或科学结论；同步不支持多人同时逐字段编辑合并。

## 0.5 工作区升级要求

1. 全局概览分别显示已知准备数量、准备数量未知的样品组、不同待测样品数量、计划操作数和未启用备样；完成、待测、进行中、跳过、中断及未处理问题分别统计。重测沿用样品 ID，启用备样才增加计划。
2. 常用记录经用户点击后创建时间线事件，不覆盖自由备注、实际参数、原始时间或开始时计划。重复点击、写入前失败和写入成功后响应丢失均有真实桌面用例；失败重试保持同一目标、内容和 request ID，保存成功才清除。
3. 问题模板预填待检查事项，允许补充文字；问题明细可定位到对应样品并标记已处理。取消后重开保留类别、模板和文字。未提交草稿仅在当前窗口保留，不自动变为事件，不宣称崩溃恢复。
4. 专注模式使用单列和较大的主要记录/控制，目标编号持续可见，并可打开队列搜索、时间线和问题；全局概览与保存状态保留。F8 忽略编辑、IME、弹窗、重复及修饰键，不能绕过忙碌、操作状态和全库单个运行约束。完成只选中完整排序的首个待测项。
5. 保留大按钮和 450 ms 保护，备注与常用入口在普通大窗口首屏可用。真实 BrowserWindow 调整大小并设置 150% 应用缩放，验证 900 × 700 请求尺寸下的重排、横向溢出、搜索与保存状态；记录原生边框尺寸舍入。专注窄窗口从页顶直接显示当前编号、主按钮和常用快记，不能仅滚到控件后宣称首屏可用；额外保存顶部及输入中原生截图。
6. 保留原有导入、导出、重启、保存失败、备份恢复、时间/计划快照、离线报告与云端边界回归。开发构建自检与最终独立打包验证分别记录，0.5 仅作为本地交付升级版，不据此声称 GitHub 发布或推送。

## 原位实验制度

样品组增加实验制度。界面把 In situ / Ex situ 显示为原位 / 非原位，保存的值不变。选原位后可写升温、保温、气氛、载荷或采集间隔；空着也能开始。具体样品留空则沿用样品组，写了字只属于这一件。改成非原位或未定不删除已写文字。

不提高 schemaVersion。旧样品组没有该字段时读作空字符串。已有 run.snapshot 不回填。新的开始把当时的有效制度写入快照，并把同一文字作为实际实验制度的初值。开始后再改计划，不改变该次快照和原始起止时间；现场若不同，只改实际实验制度。

导入认“实验制度”“实验程序”“原位制度”。没有这些列的旧表不推断制度。报告里的样品组表是当前制度；每次操作另记开始时实验制度和实际实验制度。

同一状态仍是一个样品组，不按工艺拆组。样品统称是这一组的公共名字。安排测试时每一件单独填写样品名和实验制度：编号仍按前缀加序号生成，并避开已有编号；样品名默认是统称或状态加同一序号，清空则不保存单独名字；制度留空或与样品组相同则沿用样品组。`arrange` 可以带与件数等长的 `specimens`，不带时和原来一样不写覆盖参数。开始后的快照保留当时的名字和制度。不提高 schemaVersion。
